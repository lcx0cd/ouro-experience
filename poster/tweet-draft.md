## 备选长文版（thread）

1/ 为什么我们关心 LoopLM？
Ouro-1.4B 只有 1.4B 参数，宣称"匹配 3–4B 模型质量"。秘诀：24 层权重共享，循环 4 次在潜空间"思考"。参数效率惊人，但推理时每 token 要读 4 遍权重 = 11.5GB/token。

2/ 实测速度（Apple M4, MPS, BF16）：
steps=1 → 19.4 tok/s
steps=2 → 12.3 tok/s ← 推荐
steps=3 → 8.5 tok/s
steps=4 → 6.5 tok/s
结论："慢"是物理——架构用算力换参数，不是工程没做好。

3/ 但我们差点得出错误结论。前两轮测试 Ouro 中文输出全部退化（"可能的可能的可能的…"），速度从 10.7 掉到 1.3 tok/s。
排查发现：MPS 显存污染。连续 generate 必须手动清理：
del out; gc.collect(); torch.mps.empty_cache()
否则第 N 个结果是假的。

4/ 另一个坑：提示词格式。
"事实：…问题：…" 格式 → 触发训练见过的硬编码输出（重复循环）
自然语言提问 → 同一题正常输出
用小模型，请用自然语言。格式敏感度本身就是小模型 vs 大模型的差距信号。

5/ 自适应退出"名存实亡"。
论文说平均 2.5 步达 66% 准确率。实测发布模型前两步 λ 仅 0.03/0.08，threshold=0.5 平均仍要 3.7 步。
那个 specialized 训练，根本没进发布权重。

6/ 10 题精切研究议题（中英对照）：
英文优于中文（中文训练仅 ~2%），但开放推理任务全灭——10/10 未输出可核验假设，5 题退化成阅读理解模式。

7/ 最有趣的观察：
发布 11 个月、2 万下载，没有任何针对 loop 架构的推理优化 PR / issue。
也许……其实根本没人看这些模型。
